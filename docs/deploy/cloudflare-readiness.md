# Cloudflare Production Readiness Audit

> **Date**: 2025-01-03  
> **Status**: 🟡 Needs Implementation  
> **Deployment Shape**: **B) Pages + Pages Functions** (Next.js SSR via `@cloudflare/next-on-pages`)

---

## Executive Summary

This audit identifies gaps in the Cloudflare Pages deployment configuration for the Prisma Glow Next.js 15 application. The app is already configured for Cloudflare Pages with SSR support, but requires production hardening for routing, security headers, environment variables, and CI/CD.

**Key Findings:**
- ✅ Basic Cloudflare Pages configuration exists
- ⚠️ `_redirects` file incorrectly configured for SPA (should be removed for Next.js SSR)
- ⚠️ Missing `404.html` for static fallback
- ⚠️ `_headers` exists but CSP needs tuning
- ⚠️ CI/CD workflow uses incorrect build output directory
- ✅ `wrangler.toml` configured with `nodejs_compat`
- ⚠️ Environment variables need documentation matrix

---

## 1. Frontend Application Analysis

### Framework & Build
- **Framework**: Next.js 15.5.9 (SSR mode)
- **Build Tool**: `@cloudflare/next-on-pages` v1.13.16
- **Build Command**: `pnpm --filter @prisma/web pages:build`
- **Expected Output**: `apps/web/.vercel/output/static` (generated by `@cloudflare/next-on-pages`)
- **Monorepo**: Yes (pnpm workspace, root: `/`)

### Routing
- **Type**: Server-Side Rendering (SSR) via Pages Functions
- **SPA Fallback**: ❌ **NOT NEEDED** - Next.js handles routing via Pages Functions
- **Current Issue**: `_redirects` file contains incorrect SPA fallback (`/* /index.html 200`)
- **Fix Required**: Remove SPA redirect, Next.js handles routing automatically

### Runtime Compatibility

- **Compatibility Flag**: ✅ `nodejs_compat` already enabled in `wrangler.toml`
- **Status**: ✅ Compatible

### External Backend Services
- **Supabase Edge Functions**: Separate deployment (not on Cloudflare)
- **Gateway API**: Separate Node.js server (not on Cloudflare)

## 5. Security Headers Analysis

### Current Headers (`_headers`)
✅ **Present**:
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy`
- `Content-Security-Policy` (basic)

⚠️ **Needs Improvement**:
- CSP allows `'unsafe-inline'` and `'unsafe-eval'` (should be tightened)
- Missing cache control for `index.html` (should be no-cache)
- Missing HSTS (only enable if all subdomains are HTTPS-ready)

### Recommendations
1. Tighten CSP by removing `'unsafe-eval'` if possible
2. Add `Cache-Control: no-cache` for `index.html`
3. Document CSP tuning process per environment
